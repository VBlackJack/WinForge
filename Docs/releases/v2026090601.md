# WinForge v2026090601

[French release notes](https://github.com/VBlackJack/WinForge/releases/download/v2026090601/v2026090601.fr.md)

This release fixes plugin isolation, profile data loss, process timeouts, and REST deployment execution.

## Fixed

- Sandboxed plugins no longer load into the main PowerShell session. Imports and hooks use the same validated source snapshot inside a constrained worker.
- Saving a profile or updating its application selection preserves SystemConfig and unedited custom fields. Files are replaced atomically.
- Installation, detection, package-search, and version-query deadlines remain effective while standard output and standard error are open.
- REST deployment requests now pass schema validation and start an actual background worker. Overlapping deployments are rejected, and status reports completion or failure.
- Release archives include the required JSON schemas. Missing required schemas stop validation instead of silently disabling it.

## Build and documentation

Pester is pinned to 5.7.1. ThemeForge uses an exact revision shared by CI and the local dependency resolver. Framework validation in CI no longer requires ICMP. Release packages verify required entries before generating their SHA-256 file.

README files, documentation, changelogs, and release notes use English by default with separate French versions.

## Upgrade

Extract the complete archive into a new directory. Keep your existing user profiles and settings. A fresh package is required to obtain the schemas; copying only the GUI executable is insufficient.

API clients should poll GET /api/status after a successful POST /api/deploy. A successful start response does not mean the deployment has completed. Current worker progress is 0 while running and 100 on successful completion.
